## 1. Problem Understanding & Requirements

The system processes academic manuscripts in `.docx` format to extract authorship and contribution statements, maps free-text and heterogeneous role descriptions to the standard 14 CRediT (Contributor Roles Taxonomy) categories, and outputs a canonical CSV.

### Hard Constraints & Rules
1. **Dynamic Web Scraping Required:** Must scrape the official 14 CRediT roles directly from `https://credit.niso.org/` at runtime. **Hardcoding the role list is strictly prohibited** and grounds for disqualification.
2. **Standard Output CSV Schema:**
   - Header: `file,author,credit_role`
   - One row per `(file, author, role)` triple.
   - `credit_role` must be either one of the 14 dynamically fetched standard roles or the literal string `INVALID`.
3. **Execution Script:**
   - Root level execution script `run.sh` that accepts: `./run.sh input_folder output.csv`
   - Must run cleanly on a bare Ubuntu environment with Python 3.12 and internet access.
   - `run.sh` must self-install all required Python dependencies.
4. **Mandatory Submission Deliverables:**
   - Scenario list submitted in first 30 minutes (Completed: generated `scenario_list_CS23B1035.docx`).
   - Clean git repository / shared path holding source code.

## 2. Finalized 50 Scenarios

The following 50 scenarios exhaustively test edge cases, adversarial inputs, structural document variations, network failures, and parsing anomalies.

### Area 1: Dynamic Web Scraping & Resilience (Scenarios 1–8)
1. **Scenario 1 (Happy Path Fetch):** Live HTTP GET to `https://credit.niso.org/` returns HTTP 200 with all 14 official taxonomy roles. System parses and registers all 14 roles.
2. **Scenario 2 (Complete Network Outage):** Internet is unreachable or DNS resolution fails. Tool catches `RequestException`, logs warning, and sets all output `credit_role` values to `INVALID` without crashing.
3. **Scenario 3 (HTTP Error Response):** Server returns HTTP 403, 500, or 503. System catches HTTP status error, activates failure fallback, and marks emitted roles as `INVALID`.
4. **Scenario 4 (Socket Timeout):** Remote server hangs or connection times out after 15 seconds. Tool handles timeout safely without blocking indefinitely.
5. **Scenario 5 (HTML DOM Restructuring):** Target page modifies paragraph structure to use `<h3>`, `<dt>`, or list items `<li>`. Multi-strategy scraper adapts through cascading tag selectors.
6. **Scenario 6 (Partial Taxonomy Extraction):** Website returns fewer than 10 recognizable roles due to layout disruption. Fallback triggers `INVALID` tagging rather than operating on corrupted taxonomy.
7. **Scenario 7 (Encoding Glitches on Source Website):** Website returns unicode artifacts (e.g., `\ufffd` or non-standard hyphens for dashes). Mapper normalizes characters during comparison while preserving fetched canonical names.
8. **Scenario 8 (Keyword Collision Avoidance):** Site boilerplate words (e.g., "Resources", "About", "Welcome") are distinguished so valid roles like "Resources" are never filtered out.

### Area 2: File Ingestion & Filesystem Boundary (Scenarios 9–16)
9. **Scenario 9 (Valid Standard Document):** Reads cleanly formatted `.docx` file and parses full paragraph stream.
10. **Scenario 10 (Corrupted ZIP/DOCX Archive):** File is truncated, corrupted, or non-zip (e.g., `merged_12.docx`). Tool intercepts `PackageNotFoundError` or bad zip exception, logs error, emits 0 rows, and continues pipeline.
11. **Scenario 11 (Empty Input Directory):** Input directory contains no files. Tool emits only CSV header (`file,author,credit_role`) and exits with status 0.
12. **Scenario 12 (Non-DOCX Files Present):** Folder contains `.pdf`, `.txt`, `.tmp`, or hidden temporary files (`~$merged_01.docx`). Tool filters strictly for `.docx` extension.
13. **Scenario 13 (Non-Existent Input Directory):** Given directory path does not exist. Tool reports graceful error message and exits cleanly.
14. **Scenario 14 (Blank DOCX Document):** Document contains 0 paragraphs or only whitespace. Tool emits 0 rows.
15. **Scenario 15 (Special Characters in File Path):** Directory or filename contains spaces, parentheses, or unicode. Path handling uses `os.path` without breaking.
16. **Scenario 16 (Massive File Size):** File has hundreds of body paragraphs; parser restricts section search to relevant headers rather than buffering unbounded document trees.

### Area 3: Section Identification & False-Positive Rejection (Scenarios 17–25)
17. **Scenario 17 (Standard Header Match):** Section titled exactly `Author Contributions`. Header recognized immediately.
18. **Scenario 18 (Variant Header Match):** Section titled `Author Contributions Statement` (as seen in `merged_02.docx`). Recognized via canonicalized keyword matching.
19. **Scenario 19 (Alternative Taxonomy Header):** Section titled `CRediT Taxonomy` (as seen in `merged_04.docx`). Recognized as valid contributions section.
20. **Scenario 20 (Casing Variations):** Section heading in `AUTHOR CONTRIBUTIONS` or `author contributions`. Case-insensitive pattern matching succeeds.
21. **Scenario 21 (Absence of Section):** Manuscript contains no contributions or CRediT section (e.g., `merged_03.docx`, `merged_09.docx`, `merged_11.docx`). Tool outputs 0 rows for this file (never emits phantom `INVALID` rows).
22. **Scenario 22 (Empty Contributions Section):** Section heading exists but next immediate paragraph is `Acknowledgements` or `Funding` (e.g., `merged_08.docx`). Emits 0 rows.
23. **Scenario 23 (Citation False-Positive Rejection):** Bibliography contains `[10] Smith A. Author Contributions: a practical guide. J Pub Ethics. 2019` (seen in `merged_13.docx`). Heading classifier rejects this because it begins with reference citation index `[N]` and exceeds heading length ratio. Emits 0 rows.
24. **Scenario 24 (Multi-Paragraph Section):** Contributions section spans multiple sequential paragraphs before hitting next section (seen in `merged_04.docx`, `merged_19.docx`, `merged_20.docx`). Parser buffers all intervening paragraphs.
25. **Scenario 25 (Boundary Detection on Next Section):** Section termination cleanly recognizes `Acknowledgements`, `Funding`, `Conflict of interest`, `Data availability`, `References` without prematurely truncating on sentences containing words like "funding" (resolved for `merged_19.docx`).

### Area 4: Author Extraction & Name Normalization (Scenarios 26–34)
26. **Scenario 26 (Standard Full Name):** Extracts clean two-word names like `Jane Doe` or `Raj Patel`.
27. **Scenario 27 (Dotted Author Initials):** Handles initials like `J.D.`, `A.B.`, `R.T.`, preserving punctuation and distinct tokens.
28. **Scenario 28 (Undotted Initials):** Handles compact initial groupings like `AB`, `CD`, `EF` (seen in `merged_07.docx`), matching them against author byline initials.
29. **Scenario 29 (Honorific Prefix Stripping):** Strips academic titles `Dr.`, `Prof.`, `Professor`, `Mr.`, `Ms.` (e.g., `Dr. Jane Doe` -> `Jane Doe`, `Prof. Anil Bose` -> `Anil Bose` in `merged_15.docx`).
30. **Scenario 30 (Superscript & Affiliation Stripping):** Strips trailing numerical affiliation flags and footnotes: `Jane Doe1`, `Anil Bose2†`, `Author*` -> clean names.
31. **Scenario 31 (Replacement Character in Name):** Strips unicode decoding artifacts such as `Anil Bose2\ufffd` -> `Anil Bose`.
32. **Scenario 32 (Shared Equal Contribution Statement):** Detects statement `All authors contributed equally to conceptualization, investigation and writing of the original draft` (as in `merged_17.docx`). Resolves authors from manuscript byline (`Jane Doe1, Anil Bose2`) and maps all identified roles to every author.
33. **Scenario 33 (Compound Multiple Authors in One Sentence):** Handles `AB and CD wrote and edited the paper` (in `merged_07.docx`). Resolves `AB` -> `Anil Bose` and `CD` -> `Carla Diaz`, assigning both roles to both authors.
34. **Scenario 34 (Trailing Dot Preservation on Initials):** Ensures name cleaning does not strip the closing period from initials (distinguishing `J.D.` from `J.D`).

### Area 5: Role Extraction, Mapping & Normalization (Scenarios 35–43)
35. **Scenario 35 (Direct Exact Match):** Exact string matching for standard names (e.g., `Conceptualization`, `Data curation`, `Methodology`).
36. **Scenario 36 (All-Caps & Case Discrepancies):** Handles `FORMAL ANALYSIS`, `data curation` (as in `merged_10.docx`), mapping accurately to title-cased taxonomy terms.
37. **Scenario 37 (Hyphen vs Dash Substitution):** Handles ASCII hyphen `Writing - Original Draft` vs unicode en-dash `Writing – original draft`.
38. **Scenario 38 (Encoding Glitch in Dash):** Handles corrupted dash representations like `Writing \ufffd original draft` by replacing `\ufffd` with hyphen during normalization.
39. **Scenario 39 (Qualifier & Role Degree Stripping):** Strips standard sub-role annotations: `Conceptualization – lead`, `Methodology – equal`, `Writing – original draft – supporting` (as in `merged_16.docx`), isolating pure CRediT roles.
40. **Scenario 40 (Parenthetical Role Syntax):** Extracts role terms wrapped in parentheses, e.g., `Developed the analysis code (Software) and checked results (Validation)` (as in `merged_20.docx`).
41. **Scenario 41 (Natural Language Prose Mapping):** Maps descriptive statements:
    - `designed the study` -> `Conceptualization`
    - `analyzed the data` / `performed the statistical analysis` -> `Formal analysis`
    - `wrote the initial draft` / `wrote the manuscript` -> `Writing – original draft`
    - `supervised the project` -> `Supervision`
    - `acquired funding` -> `Funding acquisition`
    - `provided resources` -> `Resources`
42. **Scenario 42 (Multi-Role Verb Conjunction):** Maps `wrote and edited the paper` to both `Writing – original draft` AND `Writing – review & editing`.
43. **Scenario 43 (Irrelevant / Unmappable Contributions to INVALID):** Non-CRediT descriptions such as `G.H. made the tea` (in `merged_18.docx`) fail keyword and fuzzy thresholds, correctly outputting `INVALID`.

### Area 6: CSV Generation, Deduplication & Pipeline Stability (Scenarios 44–50)
44. **Scenario 44 (One Row Per Author-Role Pair):** If an author has 3 roles, outputs exactly 3 distinct rows with identical file and author values.
45. **Scenario 45 (Duplicate Role Pruning):** If a role is mentioned redundantly for the same author within a file, output is deduplicated to a single row.
46. **Scenario 46 (Proper CSV Quoting):** Handles names or descriptions containing commas (e.g., `"Doe, Jane"`) using standard RFC 4180 CSV escaping.
47. **Scenario 47 (Missing Directory Creation):** Destination folder for output CSV is created automatically if parent path does not exist.
48. **Scenario 48 (Overwrite Existing CSV):** Re-running the pipeline cleanly replaces any existing file at `output.csv`.
49. **Scenario 49 (UTF-8 Output Encoding):** Output CSV is written in UTF-8 encoding ensuring en-dashes and international author characters are preserved.
50. **Scenario 50 (Deterministic Output Ordering):** Files are processed in sorted alphabetical order, ensuring reproducible CSV outputs across platforms.

## 3. Key Design Decisions Made

1. **Missing Section vs. INVALID Distinction:**
   - Files with NO contributions section (`merged_03`, `merged_09`, `merged_11`), empty sections (`merged_08`), or corrupted files (`merged_12`) emit **0 rows**.
   - `INVALID` is emitted **only** when a valid contributions section exists, but an author's stated task cannot be mapped to any CRediT role (e.g., `G.H. made the tea` in `merged_18`), OR when live web-fetching fails completely.
2. **False-Positive Heading Defense:**
   - `merged_13.docx` has the phrase `Author Contributions` inside citation `[10] Smith A. Author Contributions: a practical guide.`.
   - Decision: Check line length (< 80 chars), absence of citation brackets (`^\[\d+\]`), absence of year/volume patterns (`\d{4};\d+:\d+`), and keyword density. Result: correctly ignored, outputs 0 rows.
3. **Byline Resolution for Collective Authorship:**
   - `merged_17.docx` uses `All authors contributed equally to...`.
   - Decision: Extract canonical authors from the manuscript header byline (`Jane Doe`, `Anil Bose`) and assign every extracted role to all byline authors.
4. **Initial-to-Full-Name Linking:**
   - In prose files like `merged_07.docx` (`AB and CD wrote...`), the parser generates initials permutations (`AB`, `A.B.`, `CD`, `C.D.`) from the header byline (`Anil Bose`, `Carla Diaz`) to accurately resolve authors.
5. **Dynamic Role Binding:**
   - `mapper.py` implements a factory `build_mapper(credit_roles)`. It does not use any hardcoded taxonomy lists at import time; it binds solely to the live scraped role collection.

## 8. Known Nuances & Considerations

1. **Website Dash Encoding:**
   - The live NISO website uses an en-dash or non-standard encoding in `Writing – original draft`. The mapper accommodates both ASCII hyphens and unicode en-dashes (`\u2013`) seamlessly.
2. **Bash Script Line Endings (`run.sh`):**
   - Must be written with Unix LF line endings so it executes properly on Ubuntu without Windows CRLF carriage return errors (`^M`).
3. **Execution Environment:**
   - System requires Python 3.12 with pip available. `run.sh` must include `pip install requests beautifulsoup4 python-docx rapidfuzz`.
