# CRediT Contributor-Role Parser

**QE Hackathon — Problem 2: Parse and Normalize CRediT Contributor Roles**
Candidate: SHAIK SIFAT AHMED (CS23B1035)

Parses academic manuscripts (`.docx`), extracts authorship-contribution
statements, maps each contribution to one of the **14 official CRediT roles**
(fetched **live** from <https://credit.niso.org/>), and writes a canonical CSV.

---

## Quick start

```bash
./run.sh <input_folder> <output.csv>
```

Example:

```bash
./run.sh sample_manuscripts output.csv
```

`run.sh` runs on a bare Ubuntu environment with **Python 3.12** and internet
access. It self-installs all dependencies (`requests`, `beautifulsoup4`,
`python-docx`, `rapidfuzz`), then runs the pipeline.

> Internet is required: the 14 CRediT roles are scraped at runtime — the role
> list is **never hardcoded**. If the fetch fails, the tool still runs and emits
> `INVALID` for every role rather than crashing.

### Running without `run.sh`

```bash
python3 -m pip install requests beautifulsoup4 python-docx rapidfuzz
python3 main.py <input_folder> <output.csv>
```

## Output format

A CSV with the header `file,author,credit_role` and one row per
`(file, author, role)` triple. `credit_role` is either one of the 14 live
roles or the literal string `INVALID`.

```csv
file,author,credit_role
merged_01.docx,J.D.,Conceptualization
merged_01.docx,J.D.,Writing – original draft
merged_18.docx,Gus Hall,INVALID
```

**Zero rows vs. `INVALID`:**
- A file with **no contributions section**, an **empty section**, or a
  **corrupted/unreadable** file emits **0 rows** (never a phantom row).
- `INVALID` is emitted only when a real contributions section exists but an
  author's stated task cannot be mapped to any CRediT role, **or** when the
  live role fetch fails entirely.

## Running the tests

```bash
python3 tests/test_credit.py
```

This runs the full automated suite and writes **`test_report.csv`** to the
project root with columns `checks,input,expected,actual,result`. The process
exits non-zero if any check fails.

The suite is **offline and deterministic**: network calls are mocked, and
mapper/parser/pipeline tests use a fixed 14-role fixture list as the known
correct answer. (This fixture is test-only — the product still scrapes the
roles live.)

## How it works

1. **Fetch** (`fetcher.py`) — HTTP GET `credit.niso.org` (15s timeout),
   extract the 14 role names with cascading strategies (`<p>`, then
   `<h2/h3/h4>`, then `<li>/<dt>/…`) so minor DOM changes don't break it.
   Any network/parse failure returns `None` → safe `INVALID` mode.
2. **Read** (`reader.py`) — open the `.docx` (corruption-safe), extract the
   author byline, and isolate the contributions section. Rejects citation
   false-positives (e.g. `[10] Smith A. Author Contributions: …`) and detects
   the next-section boundary without truncating on prose that merely contains
   words like "funding".
3. **Parse** (`parser.py`) — turn the section into `(author, role_text)` pairs,
   handling structured (`Name: a, b`), parenthetical (`Name (Software)`),
   collective (`All authors …`), compound (`AB and CD …`), and prose formats.
4. **Map** (`mapper.py`) — a factory `build_mapper(roles)` bound to the live
   roles maps each fragment via exact match → keyword phrase → fuzzy match
   (RapidFuzz, 80% cutoff), stripping qualifiers (`– lead`, `– equal`) and
   normalising case/dashes/encoding artefacts. Unmappable → `INVALID`.
   Multi-role conjunctions (`acquired funding and administered the project`)
   yield every matched role.
5. **Write** (`main.py`) — deduplicate `(file, author, role)` triples, process
   files in sorted order, and write UTF-8 CSV (auto-creating the output dir).
